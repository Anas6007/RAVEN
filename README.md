# 🎁 TG Giveaway Bot

بوت تيليجرام احترافي لإدارة السحوبات في القنوات والمجموعات (قنوات/مجموعات عامة وخاصة).

---

## 🚀 التشغيل

```bash
# 1. تثبيت المتطلبات
pip install -r requirements.txt

# 2. انسخ ملف الإعدادات وعبّئ بياناتك
cp .env.example .env
# ثم افتح .env وضع فيه:
#   API_ID, API_HASH, BOT_TOKEN, BOT_USERNAME, OWNER_ID

# 3. تهيئة قاعدة البيانات
python create_tables.py

# 4. تشغيل البوت
python run.py
```

⚠️ **مهم**: البيانات الحساسة (API_ID / API_HASH / BOT_TOKEN) لم تعد مكتوبة داخل الكود،
بل تُقرأ من ملف `.env` غير المرفوع لأي مكان عام. لا تشارك هذا الملف مع أحد.

## ✨ رحلة إنشاء السحب

1. **🎁 إنشاء سحب** من القائمة الرئيسية.
2. **ربط قناة** أو **ربط مجموعة** (رابط / يوزر / رسالة محوّلة) — أو اختيار قناة محفوظة مسبقًا عبر **📂 قنواتي**.
   - يتم التحقق أن المستخدم مشرف وأن البوت مشرف قبل أي خطوة تالية.
3. اختيار **نوع السحب**: يدوي، أو تلقائي (عند عدد معين من المشاركين / عند وقت محدد).
4. إرسال **وصف السحب**.
5. إرسال **عدد الفائزين** (1 حتى 100).
6. إرسال **شروط المشاركة** (اختياري، أو "تخطي").
7. إضافة **قنوات اشتراك إجباري** (اختياري).
8. تفعيل أو تخطي **الكابتشا**.
9. **معاينة** ثم **نشر السحب** — يُحفظ رقم القناة تلقائيًا ضمن "قنواتي" لإعادة الاستخدام.

بعد النشر، تظهر 3 أزرار في رسالة السحب:
- 🎉 **المشاركة** (مع عدّاد المشاركين) — تفتح محادثة خاصة مع البوت لإتمام الشروط.
- ⛔ **إيقاف المشاركة** — لمنشئ السحب أو أي مشرف في القناة/المجموعة فقط.
- 🎲 **سحب الفائزين** — لمنشئ السحب أو أي مشرف فقط؛ يمكن الضغط عليه أكثر من مرة لسحب فائزين جدد من المتبقين حتى ينفد المشاركون.

الفائزون يُراسَلون في الخاص تلقائيًا عند السحب.

## 📈 التوسّع لحجم كبير (مئات آلاف المستخدمين / آلاف القنوات)

تعديلات هذه الجولة رفعت سقف الأداء على مستوى الكود: فهارس على أكثر
الاستعلامات استخدامًا، معالجة السحوبات المنتهية بالوقت بالتوازي بدل
التتابع، إرسال إشعارات الفائزين بأمان (مقاومة FloodWait بدل إسقاط
الرسالة بصمت)، وتفعيل إعداد `WORKERS` الذي كان معطّلاً فعليًا رغم وجوده.

لكن للوصول فعليًا لحجم بهذا الترتيب (500 ألف مستخدم، 5 آلاف قناة، آلاف
السحوبات يوميًا) يوجد قرار بنيوي واحد لا يُحل بالكود وحده:

- **قاعدة البيانات**: SQLite (الافتراضية هنا) تسمح بعملية كتابة واحدة
  فقط في نفس اللحظة مهما بلغت التحسينات. للحجم الكبير حوّل `DATABASE_URL`
  إلى Postgres (التفاصيل في `.env.example`) — هذا وحده الفارق الأكبر.
- ارفع `WORKERS` في `.env` حسب أنوية خادمك.
- Redis إلزامي عمليًا (وليس اختياريًا) عند هذا الحجم لتحديد معدّل الطلبات
  بشكل موزّع بدل كاش الذاكرة المحلي.
- جلسات إنشاء السحب (`session_manager`) حاليًا في الذاكرة داخل نفس
  العملية — مناسبة لعملية واحدة فقط. تشغيل أكثر من نسخة من البوت خلف
  موازن أحمال يحتاج نقلها لتخزين مشترك (Redis مثلًا)، وهو خارج نطاق هذه
  الجولة من التعديلات.
- سرعة إرسال الرسائل الجماعية (مثل إعلان الفائزين) محكومة بحدود تيليجرام
  نفسها للبوتات، وليست بكودنا مهما بلغ تحسين الاستضافة.

## 🛠️ ملاحظات فنية على هذا الإصلاح

كان المشروع الأصلي لا يعمل إطلاقًا بسبب استيراد ملفات غير موجودة في `run.py`، بالإضافة
إلى كمية كبيرة من الملفات المكرّرة/المهجورة وأخطاء في طبقة قاعدة البيانات. تم:

- حذف كل الملفات المهجورة/المكررة (نظام جوائز قديم غير مستخدم، مستودعات معطوبة، ملفات فارغة...).
- إصلاح صلاحيات "سحب الفائزين" و"إيقاف المشاركة" لتشمل مشرفي الدردشة وليس فقط المالك.
- جعل السحب قابلًا للتكرار (سحب فائزين آخرين) بدل إغلاق السحب من أول ضغطة.
- تفعيل السحب التلقائي فعليًا (بالعدد والوقت)، وربطه بالمجدول (`scheduler`).
- إخراج بيانات الاعتماد الحساسة من الكود إلى ملف `.env`.
- إضافة ميزة "قنواتي" لحفظ القنوات وإعادة استخدامها دون إعادة الربط.

## ✅ ما الذي أُضيف في هذه النسخة؟

- واجهة رئيسية أوضح مع خيار **إنشاء مسابقة** كمرادف عملي لـ **إنشاء سحب**.
- دعم **الصور والفيديو** في وصف السحب.
- **ترقيم صفحات** في قائمة **سحوباتي**.
- لوحة مطوّر موسّعة مع `/admin` كاختصار إضافي.
- إعادة التحقق من شروط الاشتراك الإجباري قبل اختيار الفائزين النهائيين.
- إعداد **شرط التعليق** محفوظ داخل الإعدادات ويمكن بناؤه عليه لاحقًا لربطه بمجموعة النقاش.
